## 1. 제품 정의와 결정 상태

관광객과 내국인이 서대문구·종로구·마포구·은평구의 선정 장소에서 현재 위치와 첨부 사진의 GPS 위치를 대조하고, 그 지역의 역사적 사실을 뉴스로 읽는다. 디자이너들이 역사 기사·GPT Image 삽화·신문 템플릿을 사전에 제작하고 검토한다. 방문 시 해당 거점에 게시된 완성 신문 중 하나를 랜덤으로 선택하여 보여주고, 신문 아래에서 주변 소상공인 음식점 후보를 추천한다. 챗봇은 무장애 여행 데이터와 음식점 메타데이터를 함께 참조하여 장애인을 포함한 이용자의 관광 코스를 제안하고 네이버 지도에 장소 핀을 표시하고 방문 순서는 목록으로 제공한다. 서비스명은 미정이다.

## 2. 목표와 MVP 범위

목표는 장소의 역사 발견 경험을 주변 음식점과 접근성 조건을 고려한 지역 관광 코스로 연결하는 것이다. 기존 촬영지 중심 탐색, 음식 취향 해석, 상인 등록·검수·주문 카드는 이번 MVP 핵심 흐름에서 제외하고 후속 검토로 이동한다.

- P0: 서대문구·종로구·마포구·은평구 거점 탐색. 선호 K콘텐츠의 시대 배경을 선택·확인하여 신문을 매칭.
- P0: 현재 위치 요청, 선택적 사진 첨부와 GPS 추출, 위치 비교 상태, 지원 장소 판정.
- P0: 출처가 확인된 역사 자료 선택, 역사 사건 최소 1개를 확보한 거점 등록, 사전 제작 신문 게시, 거점·선호 시대에 맞는 완성 신문 후보 안에서 랜덤 표시와 출처 확인.
- P0: 서버가 주변 음식점 후보를 추린 뒤 메타데이터를 챗봇 컨텍스트로 전달. 챗봇은 후보 ID를 참조하여 추천 설명과 카드를 제공. 초기 카드 3~5개는 제안이다.
- P0: 네이버 지도에 관광 거점·관광지·음식점 핀 표시. 방문 순서는 번호가 있는 목록으로 제공하며 지점 사이 연결선·실제 경로선은 표시하지 않음.
- P0: 이동·접근성 조건을 반영한 관광 코스 챗봇. 필수 조건이 확인된 장소를 우선하며 장소별 미확인 조건과 장소 사이 이동은 별도 확인이 필요함을 표시.
- P0: GPS 누락·불일치의 현재 위치 대안, 위치 권한 거부, 지원 장소 밖, 게시 신문 없음, 신문·이미지 조회 실패 복구.
- 후속: 추가 지역·언어, 저장·공유·수집함, 메뉴별 취향 추천, 상인 등록.

성공 기준: 정상 입력에서 근거와 연결된 기사 및 삽화가 나타나고, 음식점 카드로 이어진다. 오류 상황에서 가짜 기사·좌표·영업 정보가 만들어지지 않는다. 사용자 신문 조회 경로에는 실시간 기사·이미지 생성 호출을 두지 않는다. 조회 시간은 구현 후 측정한다.

## 3. 사용자 흐름과 위치 정책

1. 사용자가 위치 사용 목적을 확인하고 현재 위치 권한을 허용한다. 사진은 원하는 경우에만 첨부하며, 첨부하지 않고 신문 열람을 시작할 수 있다.
2. 사진을 첨부하고 GPS가 있을 때 현재 위치와 비교한다. GPS가 없거나 달라도 현재 위치를 기준으로 진행할 수 있다.
3. 현재 위치가 포함되는 지원 장소를 결정하고 장소명과 위치 확인 상태를 보여준다.
4. 사용자가 선택한 K콘텐츠의 검토된 시대 배경을 확인한다. 해당 거점·선호 시대·요청 언어에 연결된 게시 완성 신문 중 하나를 랜덤 선택한다. 1개면 그 신문을 표시하며 미선택 시 거점의 일반 게시 후보에서 선택한다.
5. 선택한 신문의 템플릿·기사·삽화를 함께 불러와 신문 펼침 전환으로 보여준다. 제작 중인 콘텐츠는 선택하지 않는다.
6. 신문에서 역사 사건과 출처, AI 생성 삽화 표시를 확인한다. 하단에서 주변 음식점을 확인하고, 챗봇에 이동 조건과 관심사를 입력하여 관광 코스를 추천받는다. 네이버 지도와 순서 목록에서 코스를 확인한다.

현재 위치가 지역 선택의 기준이다. 다른 장소의 사진 GPS로 지역을 바꾸지 않는다. GPS 일치만으로 실제 방문·실시간 촬영·사진 진위를 보증하지 않는다. 사진 첨부는 선택이다. 위치 거부 시 직접 장소 선택을 허용할지는 아직 결정하지 않았다.

| 상태 | 처리 |
| --- | --- |
| 사진 GPS 일치 | photo_matched. 제안된 허용 거리 이내인지 확인하고 현재 위치의 장소로 진행. |
| 사진 미첨부 | current_location_only, reason=photo_not_provided. 정상적인 기본 흐름으로 진행하며 사진 업로드를 요구하지 않음. |
| GPS 없음·불일치·사진 파싱 실패 | current_location_only. 원인을 알리고 현재 위치로 진행 허용. 일치 배지는 표시하지 않음. |
| 현재 위치 정확도 부족 | location_uncertain. 새 위치 요청 또는 재시도. 허용 거리를 무제한 확대하지 않음. |
| 위치 권한 거부·획득 실패 | 위치 기반 열람 보류, 재시도 안내. 수동 체험 모드는 미결정. |
| 지원 장소 밖 | 지원 장소 목록 안내. 가장 가까운 장소의 사건을 현재 장소 사건으로 소개하지 않음. |

좌표는 WGS84, 거리는 미터로 통일한다. 비교는 좌표 거리 계산으로 수행한다. 사용자가 확정한 현재 위치 정확도 상한은 20m이다. 브라우저가 반환한 accuracy가 20m 이하일 때 위치 판정에 사용하고, 20m를 초과하면 위치 재취득을 안내한다. 사진 비교 반경 200m는 제안값이며 미확정이다. 거점 방문 반경도 별도 설정으로 결정한다. 장소별 서비스 영역과 사진 비교 반경은 별도 값이다. 두 위치가 가깝더라도 지원 장소 영역 밖이면 신문 제공 대상이 아니다. 인접 영역이 겹치면 후보 장소를 보여주고 사용자가 확인한다.

## 4. 데이터 확보와 품질 기준

### 거점 스팟 등록·게시 조건

거점은 역사 사건과 연결된 실제 방문 위치다. 단순 행정구역 키워드가 아니라 방문 가능한 지점의 좌표·범위·안전한 접근 위치를 정한다. 사건 장소가 소실·이전된 경우 현재 거점과 당시 위치의 관계를 명시한다.

- 필수: 거점 ID·명칭·좌표·서비스 반경, 검토된 역사적 사건 최소 1개, 사건 날짜와 정밀도, 장소 연결 근거·출처.
- 공개 필수: 거점에 연결된 완성 신문 최소 1개. 템플릿·본문·AI 삽화·출처·언어·버전과 게시 상태를 함께 관리한다.
- 후보 선별: 원문 확보 가능성, 장소 연결 정확도, 현장 접근성, 주변 음식점 데이터 활용성을 검토한다. 주변 음식점이 없으면 빈 결과를 표시할 수 있다.
- 공개 하한은 검토된 사건·완성 신문 각 1개지만, 거점 선정에서는 여러 시대의 사건과 사료를 확보할 수 있는 장소를 우선한다. 초기 제작 목표로 거점당 2개 이상 시대를 제안하며 확정된 최소 개수는 아니다. 여러 디자인만 있고 사건 시대가 같은 경우는 시대 다양성으로 계산하지 않는다.

랜덤 선택 단위는 사전 검토한 완성 신문이다. 제목·본문·이미지를 각각 무작위로 섞지 않는다. 다른 장소·시대 불일치·미게시·미검토·삭제된 콘텐츠는 후보에서 제외한다. 요청 언어의 신문이 없으면 언어 선택 안내를 제공하며 다른 언어로 조용히 대체하지 않는다. 연속 중복 방지와 가중치는 미결정이며 새로고침 시 선택한 신문 ID를 유지하는 안을 제안한다.

국가기록원 API는 검색 메타데이터와 상세 링크를 제공한다. 제목·생산연도만으로 사건 전체를 기사화하지 않는다. 문서상 좌표·사건 발생일·본문·이미지 URL은 별도 확인이 필요하다. 생산연도와 사건 발생일을 분리한다. API 요청 한도에 맞춰 사전 수집·캐시하는 방식을 제안한다.

역사 사실마다 장소와 연결되는 근거, 확인된 사실, 사건 날짜의 정밀도, 원문 링크, 확인일, 검토 상태를 저장한다. 검토된 사실만 사전 기사 제작에 사용한다. 제작한 기사 문장은 근거 ID를 참조하며, 확인되지 않은 인용·인물 행동·날짜를 추가하지 않는다. 출처 링크 존재만으로 기사 내용의 진실성이 검증된 것으로 취급하지 않는다.

음식점 데이터의 지점 표기 필터는 프랜차이즈 판별이나 소상공인 인증이 아니다. 확인 전 공개 표현은 ‘주변 음식점’으로 하고 소상공인 확정 배지를 붙이지 않는다. 메뉴·가격·리뷰·영업시간·역사적 연관성이 없으면 생성하지 않는다. 역사 사건과 음식점은 위치로 연결하며 당대에 존재한 가게로 묘사하지 않는다.

## 4-1. 거점의 시대 다양성과 K콘텐츠 매칭

핀 후보는 서울 서대문구·종로구·마포구·은평구로 한정한다. 각 후보는 장소의 실제 좌표·행정구·시대별 사건·원문 근거를 확인한다. 4개 구 전체나 특정 장소의 데이터 확보가 끝난 상태는 아니다. 구별 개수와 실제 장소는 조사 후 정한다.

K콘텐츠는 취향을 시대와 연결하는 진입점이다. 작품 속 시간 배경과 거점에서 실제 일어난 역사 사건의 시대를 매칭한다. 작품의 촬영 장소·실제 사건 발생 장소·가상 이야기의 배경은 서로 다른 관계이며 동일하다고 추정하지 않는다. 작품에 등장하지 않은 거점도 같은 시대의 역사를 보여줄 수 있으나 그 이유를 설명한다.

작품별 시간 배경은 검토한 목록으로 시작하고 여러 시대·현대와 과거가 섞인 작품은 사용자가 시대를 확인·선택한다. 허구의 왕조·연도가 불명확한 작품은 역사 연대로 강제 변환하지 않고 직접 시대 선택을 제공한다. 작품 메타데이터 출처와 실제 역사 출처는 별도로 보존한다.

시대는 공통 eraId와 필요 시 시작·종료 연도로 관리한다. K콘텐츠는 여러 시대에 연결될 수 있고 사건과 신문에도 검토한 시대를 연결한다. 거점의 건립 시대만으로 그곳의 모든 사건을 같은 시대로 지정하지 않는다. 실제 사건이 원문으로 확인된 시대만 신문 후보가 된다.

선택한 시대의 신문이 없으면 해당 거점에 그 시대 신문이 없다고 안내하고 다른 시대 또는 다른 거점을 선택하도록 한다. 다른 시대 신문을 조용히 대신 보여주거나 실시간으로 새 사실을 생성하지 않는다. 템플릿·기사·이미지는 계속 사전 제작하며 랜덤은 시대 필터를 통과한 완성본 안에서만 수행한다.

## 5. 신문 구성과 모션 UX

신문 구성 순서는 제호·지역·콘텐츠 발행일 → 역사 사건 날짜 → 헤드라인·리드 → 역사 삽화 → 기사 본문 → 기록 출처 → 주변 음식점이다. 콘텐츠 발행일·방문일·과거 사건의 날짜를 구분하고 방문할 때마다 새로 작성한 기사처럼 표시하지 않는다.

신문은 디자이너가 제공하는 SVG를 기반으로 모션과 인터랙션을 구현한다. 애니메이션·클릭 대상에 안정적인 그룹 ID를 부여하고 React에서 연결한다. SVG를 단일 이미지로만 표시하면 내부 요소 제어가 제한되므로 조작 대상은 인라인 SVG 등 요소 접근이 가능한 형태로 인계한다. 본문·출처는 SVG 텍스트 또는 대응 HTML로 읽을 수 있게 제공하며, 글자가 경로로 변환된 경우 동등한 텍스트와 링크를 별도로 둔다. 모바일 읽기와 키보드 조작도 유지한다. 외부 SVG의 스크립트·이벤트 속성은 제거하고 검토된 정적 자산만 배포한다. 모든 생성 삽화에 ‘AI가 재구성한 역사 삽화’를 표시하고 실제 사료 사진과 구분한다. 출처로 확인하지 못한 세부 장면을 사실의 증거로 제시하지 않는다.

제안 화면: H01 위치·사진 입력, H02 위치 결과와 장소 확인, H03 게시 신문 불러오기, H04 신문과 음식점, H05 출처·가게 상세. 기존 S01~S09 와이어프레임은 이전 제품 설계이며 이번 요구의 구현 기준이 아니다.

모션은 장소 확인 → 신문 펼침 → 헤드라인과 삽화 노출 → 음식점 카드 등장으로 이어지는 짧은 전환을 제안한다. 로딩에는 실제 처리 상태를 사용하고 가짜 완료율을 표시하지 않는다. 모바일 본문은 단일 컬럼으로 읽고 넓은 화면에서 신문 지면처럼 확장한다. reduced-motion 설정에서는 펼침·이동 효과를 줄이고 내용 접근을 유지한다. 기사·출처는 키보드와 스크린리더로 접근 가능해야 한다.

## 5-1. 접근성 조건을 반영하는 관광 코스 챗봇

사용자는 음식점 추천뿐 아니라 역사 거점·관광지·식사·휴식을 묶은 관광 코스를 요청할 수 있다. 장애 유형을 진단하거나 일괄 분류하기보다 실제 이동 조건을 선택·입력받는다. 예: 휠체어 이동, 계단 회피, 접근 가능한 화장실 필요, 짧은 이동 구간 선호, 동행 여부, 식사 업종·시간 예산. 구체적인 입력 항목은 UX 설계안이며 필수 조건과 선호 조건을 구분한다.

1. 서버가 현재 지역의 역사 거점·관광지·음식점 후보를 조회하고 공개 여부·좌표·데이터 연결을 검사한다.
2. 접근성 원문과 출처·확인 시점을 정규화하여 제공·미제공·미확인 상태로 분리한다. 빈 값은 이용 가능이나 이용 불가로 단정하지 않는다.
3. 서버는 이용자가 지정한 필수 조건 위반·미확인 장소를 적합 후보에서 제외한다. 후보가 부족하면 조건을 자동 완화하지 않고 확인 필요 장소를 별도로 제시하거나 재선택을 안내한다.
4. LLM은 전달된 후보와 근거 안에서 방문 순서·추천 이유·식사 지점을 제안한다. 서버가 반환한 장소 ID·필수 조건·접근성 근거를 재검사한 뒤 지도와 코스 카드로 표시한다.

관광공사 무장애 상세정보는 관광지 내 시설의 근거로 사용한다. 이 정보만으로 장소 사이 보도·경사·횡단보도·엘리베이터 연결이 검증된 것은 아니다. 관광지와 가까운 음식점도 접근 가능한 음식점으로 자동 판정하지 않는다. 별도 근거가 없는 음식점의 출입구·화장실·좌석 접근성은 미확인이다.

네이버 지도는 장소 핀 표시에 사용한다. 경로선·지점 간 연결선·길찾기·이동시간 산출은 이번 범위에서 제외한다. 경로 데이터 제공자 선정과 TMAP 연동도 제외한다. 코스는 방문할 장소의 순서 제안으로 제공한다. 직선거리를 도보시간으로 변환하거나 LLM이 이동시간·무장애 경로를 추정하여 확정하지 않는다.

코스 응답은 장소별 접근성 상태·근거·미확인 항목을 가진다. 필수 조건이 확인된 장소로 방문 순서를 제안하되 장소 사이 이동의 접근성은 검증 범위에 포함하지 않는다. ‘방문 순서 제안 · 장소 사이 이동은 별도 확인 필요’라고 표시하며 무장애 이동이 보장된 길찾기로 소개하지 않는다. 모든 코스에 역사 신문이 있는 거점을 최소 1개 포함하는 안은 제안이며 미확정이다.

화면은 네이버 지도·방문 순서 목록·장소별 접근성 정보·챗봇으로 구성한다. 지도 사용이 어려워도 목록으로 코스 내용을 확인하고 장소를 선택할 수 있어야 한다. 사용자의 필수 조건은 대화 위에 요약하고 직접 변경할 수 있게 한다.

| 수집·제작 | Python 사전 수집·정제, 역사 사건 검토, 디자이너의 템플릿·기사·GPT Image 삽화 사전 제작과 게시. 전용 관리 화면 대신 파일·JSON 인계 가능 여부는 논의 중. |

| DB·파일 | MySQL 사용 확정. Spring에서 연결하며 Supabase PostgreSQL은 채택하지 않는다. 정적 SVG·이미지 저장소/CDN 공급자는 미정. 소수 거점의 좌표 거리 계산부터 시작한다. 공급자·배포는 미결정. |
| AI | GPT Image는 제작 단계에서 사용. 실행 중 LLM은 음식점·관광지·접근성 데이터 기반 코스 추천 챗봇에 사용하며 텍스트 모델은 미선정. |

```text
사전 준비: 역사 기록·상권·관광 API → 수집·검토 → 거점·사건·음식점 데이터
신문 제작: 검토된 사건 → 디자이너의 기사·템플릿·AI 삽화 → 검토·게시
방문 열람: React → Spring 위치 판정 → 거점의 게시 신문 랜덤 선택 → 완성 신문 표시
코스 대화: Spring 지역·필수 조건 후보 필터 → 음식점·관광지·무장애 근거 + 사용자 조건 → LLM → 후보·조건·접근성 근거 검증 → 네이버 지도·방문 순서 카드
```

신문 조회에는 생성 작업 큐·상태 polling·이미지 생성 대기 화면을 두지 않는다. 제작 파이프라인의 필요 도구는 별도로 결정한다. 위치·반경·게시 여부·음식점 후보 필터는 서버가 결정한다. 챗봇에는 상호·업종·장소 ID·주소·서버 계산 거리·기준일·접근성 원문과 상태·출처·필요한 이동 조건만 전달한다. 정확한 사용자 위치 대신 서버가 조회·계산한 후보와 거리만 제공하는 안이다. 서울 전체 음식점이나 사용자 정확 좌표·사진 EXIF·인증키를 모델에 전달하지 않는다. 후보 밖 ID와 근거 없는 메뉴·가격·영업시간은 응답에서 허용하지 않는다. 사용자 대화 이력 보관 정책은 미결정이다. 이동 지원 조건은 세션 처리에 필요한 범위로 사용하고 장애 진단명·상세 건강정보 입력을 요구하지 않는다. 이동 조건을 로그·장기 프로필에 기본 저장하지 않는다.

| KContent | id, title, type, settingEraIds, settingStartYear, settingEndYear, settingEvidence, reviewStatus. 실제 촬영지 여부와 별도. |

Place는 Spot으로, HistoricalFact는 HistoricalEvent·SpotEvent로 정리하는 문서 제안이다. 실제 DB 마이그레이션을 수행한 것은 아니다. GenerationJob은 방문 열람 계약에서 제거한다.

API 제안: 위치 판정 → locationCheckId·spotId·mode. 신문 선택 요청은 locationCheckId·spotId·language와 선택적 eraId·kContentId를 받고 editionId와 완성 신문을 반환한다. 콘텐츠의 검토된 시대와 사용자가 확인한 시대를 적용하며 서버가 재검사한다. 서버는 위치 판정 결과와 거점의 게시 후보를 확인한다. editionId로 해당 버전을 다시 조회할 수 있다. 네이버 지도와 음식점 조회는 spotId 또는 현재 위치 기준을 명시한다. 코스 추천 API는 이동 조건·후보 ID·방문 순서·장소별 접근성 근거·미확인 항목을 반환한다. 챗봇 응답의 추천 ID는 서버가 전달한 후보 집합에 포함되는지 검증한다. 위치 판정은 조작 방지 보증이 아니다.

<a id="privacy"></a>

## 8. 파일·위치·장애 처리

사진 EXIF는 리사이즈·재인코딩 전에 추출해야 한다. 브라우저 추출 후 좌표만 보내는 안과 원본을 서버에서 파싱하는 안 중 선택이 필요하다. 브라우저가 보낸 값도 위조될 수 있다. 기본 제안은 원본 사진과 정확 좌표의 장기 저장을 피하고, 이용 기록에는 검증 상태와 거점 ID만 남기는 것이다. 사전 제작 신문 데이터에 개별 사용자의 위치를 포함하지 않는다. 실제 처리·삭제 시점은 업로드 구조 결정 후 문서화한다.

지원 형식·파일 크기 제한·실제 포맷 검사·파싱 실패 처리가 필요하다. JPEG부터 시작하고 HEIC 등은 지원 검증 후 확장하는 안이다. 지원하지 않는 파일이나 GPS 누락 때문에 현재 위치 기반 대안을 막지 않는다. 사용자 사진을 AI 서비스에 보내는 기능은 현재 요구에 포함하지 않는다.

| 실패 | 복구 |
| --- | --- |
| 검토된 사건·게시 신문 없음 | 거점을 공개하지 않거나 제공 불가 안내. 실시간 기사 생성으로 대체하지 않음. |
| 삽화 파일 조회 실패 | 선택한 기사·출처 유지, 이미지 재시도 또는 자리표시자. 다른 사건 삽화를 임의로 붙이지 않음. |
| 음식점 없음·챗봇 실패 | 신문 유지. 음식점 빈 결과와 대화 오류를 구분하고 조회된 카드는 유지. |
| 새로고침·재방문 | 같은 열람에서는 editionId 유지 제안. 새 선택의 중복 방지 규칙은 미결정. |

## 9. 수용 기준과 검증

- AC-01: 사진 없이 현재 위치만으로 신문 열람 가능하다. 사진 미첨부와 사진 GPS 일치·없음·불일치·파싱 실패를 구분하며, 미첨부 시 GPS 추출·비교를 건너뛴다. GPS 없음·불일치·파싱 실패도 현재 위치로 진행 가능하다.
- AC-02: 좌표 누락·잘못된 범위·거리 경계·낮은 위치 정확도·지원 장소 밖을 테스트한다. 허용 기준은 설정값으로 관리한다.
- AC-03: 게시 거점은 검토된 역사 사건 최소 1개와 완성 신문 최소 1개를 가진다. 미검토 사실은 기사 제작·게시에서 제외한다. 기사 각 핵심 주장에 근거가 연결되고 사건 날짜와 생산연도를 혼동하지 않는다.
- AC-04: 모든 생성 삽화에 AI 표시가 있다. 삽화 파일 조회 실패 후 기사·출처·음식점 접근이 유지된다.
- AC-05: 음식점 거리 기준점과 직선거리임을 표시한다. 없는 메뉴·가격·영업시간·소상공인 인증을 생성하지 않는다.
- AC-06: 랜덤 결과는 현재 거점·확인한 선호 시대·요청 언어·게시 상태의 완성 신문에 한정된다. 후보 1개이면 정상 표시하고 0개이면 제공 불가를 표시한다. 템플릿·기사·삽화·출처 묶음을 유지하며 신문 조회에서 AI 생성 API를 호출하지 않는다.
- AC-07: 로그·공개 신문·외부 AI 요청에 API 키, 원본 EXIF, 정확 사용자 좌표가 포함되지 않는다.
- AC-08: 모바일 390px, 넓은 화면, 키보드, reduced-motion에서 읽기와 핵심 이동을 검증한다.
- AC-09: LLM의 관광지·음식점 ID가 서버 후보에 속하고 사용자의 필수 조건을 위반하지 않는다. 자료의 빈 값을 접근 가능으로 해석하지 않는다.
- AC-10: 관광지의 시설 접근성만으로 음식점 또는 연결 구간의 접근성을 확정하지 않는다. 장소 사이 이동은 별도 확인이 필요함을 표시하고 이동시간을 만들어내지 않는다.
- AC-11: 네이버 지도 핀과 순서 목록이 같은 장소를 가리키며 경로선·연결선은 표시하지 않는다. 경로 API 호출 없이 동작하고 지도 실패 시 목록과 접근성 근거를 유지한다.
- AC-12: 접근성 필수 조건을 만족하는 후보가 없으면 조건을 자동 완화하지 않는다. 챗봇 실패 시 신문과 조회된 장소·음식점 카드를 유지한다.
- AC-13: 공개 역사 핀은 서대문구·종로구·마포구·은평구 범위에 한정한다. 시대 다양성은 검토된 사건·신문에 근거해 집계한다.
- AC-14: K콘텐츠의 여러 시대·가상 시대·미확인 시대를 구분한다. 선호 시대가 확정되면 같은 거점의 해당 시대 게시본 안에서만 선택하고, 미보유 시 명시적으로 다른 선택을 안내한다. 촬영지·가상 사건을 실제 역사로 소개하지 않는다.

현재 검증은 문서와 로컬 데이터 메타정보 확인까지다. 관광공사 API 목록·무장애 상세 샘플 조회는 통과했다. 실제 무장애 이동 경로나 현장 코스를 검증한 것은 아니다. 실제 역사 사건 수집·검토, 위치·사진 처리, 신문 제작·랜덤 조회, 챗봇·앱 동작은 검증하지 않았다.
